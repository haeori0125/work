# 팀 투두리스트 사이트 — 설계 문서

작성일: 2026-11-23 · 상태: 승인됨

## 1. 목적과 배경

모임 구성원 여러 명이 함께 쓰는 업무 체크 사이트(비상업적 용도, Vercel 무료 요금제 사용). 문서에서 "직원"은 일반 구성원, "관리자"는 운영진을 뜻한다. **화면 문구는 "멤버 / 관리자"를 사용한다** (예: 로그인 탭 "멤버 / 관리자", "멤버 관리"). *(사용자 결정)* 직원은 출근하면 로그인하고, 그날 해야 할 업무를 가장 먼저 확인한 뒤 진행 상황을 체크한다. 누가 무엇을 체크했는지, 누가 언제 출근·퇴근했는지가 기록으로 남아야 한다. 업무와 일정은 관리자가 만든다.

성공의 모습: 직원은 로그인 직후 "오늘 할 일"을 바로 보고 한두 번의 클릭으로 상태를 바꾼다. 관리자는 업무를 한 번 등록하면(반복 포함) 매일 다시 입력할 필요가 없고, 누가 무엇을 했는지와 출퇴근 시간을 한눈에 본다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 이름 + 비밀번호 로그인, 로그인 화면에 직원 / 관리자 탭
- 오늘 업무 최우선 표시, 주간 업무와 위클리(요일별) 보기 함께 제공
- 업무 상태 3단계(미체크 → 진행 중 → 완료), 상태를 바꾼 사람과 시간 표시
- 관리자: 업무 작성·수정·삭제, 반복 설정, 담당자 지정
- 메모 3종: 업무별 메모, 날짜별 공용 메모판, 개인 메모
- 출근(첫 로그인) / 퇴근(버튼) 기록, 직원은 본인 기록 조회, 관리자는 전체 조회·수정

**비목표 (이번 범위 아님)**
- 이메일·SNS 로그인, 비밀번호 찾기 메일 (비밀번호 재설정은 관리자가 해 줌)
- 푸시 알림, 메신저 연동
- 급여·근태 정산 계산, 엑셀 내보내기
- 여러 팀·지점 분리 (한 팀 한 사이트)

**실패 조건 (동작은 해도 실패로 보는 경우)**
- 로그인 후 오늘 업무를 찾으려고 스크롤·탭 이동을 해야 함
- 체크 기록에 남는 사람이 실제로 누른 사람과 다를 수 있음 (다른 사람 계정으로 쉽게 체크 가능)
- 반복 업무의 상태가 날짜 간에 섞임 (월요일 완료가 화요일에도 완료로 보임)
- 휴대폰에서 쓰기 불편함

## 4. 접근 방식

| 방식 | 장점 | 단점 |
|---|---|---|
| **A. Next.js + Neon Postgres(Vercel Storage), 로그인 직접 구현** ✅ 선택 | Vercel 한 곳에서 관리, 이름+비밀번호 로그인을 그대로 구현 | 로그인 코드를 직접 작성 |
| B. Next.js + Supabase | 검증된 로그인, 데이터 관리 화면 | 이메일 기반이라 이름 로그인은 우회 필요, 계정 하나 더 |
| C. 정적 HTML + Firebase | 가장 가벼움 | 권한·기록 관리가 커지면 복잡, 확장 어려움 |

사용자가 A를 선택. 이유: 원하는 로그인 방식과 가장 잘 맞고, 관리 지점이 Vercel 하나로 끝남.

## 5. 결정된 사항 (사용자 결정)

### 5.1 계정과 로그인
- 로그인: 이름 + 비밀번호. 로그인 화면에 **직원 / 관리자** 탭.
  - 관리자 탭으로 로그인하면 관리자 계정인지 확인하고, 아니면 거절.
  - 직원 탭으로는 관리자도 일반 화면으로 로그인 가능 (선택: 빌더 판단).
- 직원은 처음에 이름과 비밀번호를 정해 **가입 신청**. **관리자가 승인해야** 로그인 가능. 승인 전에는 "승인 대기 중" 안내만 보임. 관리자는 신청을 승인 또는 거절. *(사용자 결정)*
- 각자 자기 기기를 사용하므로 공용 기기 대비 자동 로그아웃은 두지 않음. *(사용자 결정)*
- 첫 관리자 계정은 Vercel 환경변수(`ADMIN_NAME`, `ADMIN_PASSWORD`)로 최초 1회 생성. 관리자는 다른 직원을 관리자로 지정·해제 가능. *(제안 — 사용자가 이의 없음)*
- 이름은 팀 안에서 중복 불가 (로그인 ID 역할).

### 5.2 업무
- **처리 방식: 함께 처리.** 업무(한 회차)마다 상태는 하나. 누가 바꾸든 모두의 화면에 같은 상태가 보이며 "진행 중 · 김철수 09:14"처럼 마지막으로 바꾼 사람·시간 표시.
- **담당자 지정(선택):** 관리자가 업무에 담당자(1명 이상)를 지정할 수 있음. 지정 시 "담당: 영희" 표시. 담당자가 있어도 **누구나 상태 변경 가능**하고, 기록에는 실제로 바꾼 사람이 남음. *(제안 — 사용자가 이의 없음)*
- **상태:** 미체크 / 진행 중 / 완료. 아무 단계로나 이동 가능 (완료 → 진행 중 되돌리기 포함).
- **변경 이력:** 상태가 바뀔 때마다 (누가, 언제, 이전 → 이후) 저장. 화면에는 마지막 변경자를 기본 표시하고, 펼치면 이력 확인.
- **업무 종류**
  - **날짜 업무:** 특정 날짜에 하는 업무.
  - **주간 업무:** 날짜 없이 그 주(월~일) 안에 끝내면 되는 업무.
- **반복:** 관리자가 등록할 때 선택.
  - 날짜 업무: 반복 안 함 / 매일 / 평일만(월~금) / 매주 선택 요일(복수 선택 가능)
  - 주간 업무: 반복 안 함 / 매주
  - 반복 업무는 **회차마다 상태가 새로 시작** (월요일 완료 ≠ 화요일 완료).
  - 반복에는 시작일이 있고, 종료일은 선택.

### 5.3 화면 구성 (직원)
로그인 직후 메인 화면, 위에서부터:
1. 상단: 이름, 오늘 날짜, 출근 시간, **퇴근 버튼**
2. **오늘 업무** — 최우선. 미완료가 위, 완료는 아래로.
   - 그 위(또는 바로 아래)에 **지난 업무**: 기간이 지났는데 완료되지 않은 **일회성** 업무(날짜 업무·주간 업무 모두). 완료하면 목록에서 빠짐. 반복 업무의 지난 회차는 넘어오지 않음. *(사용자 결정: 명칭은 "지난 업무")*
3. **이번 주 업무(주간 업무)**
4. **위클리 보기** — 이번 주 월~일 날짜 업무를 요일별로 (탭 또는 접힘 영역으로 전환 가능)
5. **오늘의 공용 메모판**

그 밖의 화면: 개인 메모, 내 출퇴근 기록.

```
┌───────────────────────────────────────┐
│ 김철수 · 11/23(월) · 출근 09:02 [퇴근] │
├───────────────────────────────────────┤
│ 지난 업무                              │
│ ○ 비품 주문 (11/21)                    │
├───────────────────────────────────────┤
│ 오늘 업무                              │
│ ○ 매장 오픈 준비        담당: 영희      │
│ ◐ 재고 확인   진행 중 · 철수 09:14  💬2 │
│ ● 청소       완료 · 민수 08:55         │
├───────────────────────────────────────┤
│ 이번 주 업무                           │
│ ○ 주간 재고 점검                       │
├───────────────────────────────────────┤
│ 위클리  [월][화][수][목][금][토][일]     │
├───────────────────────────────────────┤
│ 오늘의 공용 메모                        │
└───────────────────────────────────────┘
```

### 5.4 메모
- **업무별 메모:** 업무 회차마다 댓글처럼 여러 개. 작성자·시간 표시.
- **공용 메모판:** 날짜별 하나의 게시판(여러 글). 팀 전체가 봄.
- **개인 메모:** 본인만 볼 수 있는 메모장.
- 수정·삭제: 업무별·공용 메모는 작성자만 수정/삭제, 관리자는 모두 삭제 가능. 개인 메모는 본인만.

### 5.5 출퇴근 기록
- **출근:** 그날(한국 시간) **첫 로그인 시간**이 출근 시간. 이후 로그인도 접속 기록으로 모두 저장.
- **퇴근:** 메인 화면의 퇴근 버튼으로 기록.
- **퇴근 미기록:** 자정(한국 시간)까지 퇴근 버튼을 누르지 않으면 그날은 "퇴근 미기록"으로 표시.
- **근무 시간:** 출근~퇴근 차이를 "9시간 8분"처럼 표시.
- **직원:** 본인 기록을 날짜별로 조회.
- **관리자:** 전체 직원 기록 조회, 출근·퇴근 시간 수정 가능 (수정 이력 남김: 누가, 언제, 원래 값).

### 5.6 관리자 화면
- 업무 관리: 작성 / 수정 / 삭제, 종류(날짜·주간), 반복, 담당자
- 직원 관리: **가입 신청 승인·거절**, 목록, 관리자 지정·해제, 비밀번호 재설정, 계정 비활성화
- 출퇴근 기록: 전체 조회, 수정
- 관리자도 일반 업무 화면 사용 가능

## 6. 빌더 판단 사항 (구현 시 결정)

- 기술: Next.js(App Router, TypeScript), Neon Postgres, ORM(Drizzle 권장), 비밀번호 해시(bcrypt 계열), 세션은 httpOnly 쿠키 + DB 세션 테이블 권장
- 반복 업무는 회차를 미리 만들지 않고, 업무 정의 + (업무, 회차 날짜)별 상태 행으로 저장하는 방식 권장. 주간 업무의 회차 키는 그 주 월요일 날짜
- "퇴근 미기록"은 배치 작업 없이, 날짜가 지났는데 퇴근 시간이 없으면 미기록으로 계산해 표시하는 방식 권장
- 반복 업무 수정·삭제 시 과거 회차의 상태·메모 기록은 보존
- 화면 디자인 세부, 색, 아이콘
- 휴대폰 화면 대응(반응형) 필수
- 실시간 갱신은 필수 아님 — 화면 포커스 시 / 주기적 새로고침 정도면 충분
- 로그인 시도 제한 등 기본 보안 조치

## 7. 검토 후 정한 사항 (Claude 판단 — 확인 필요)

- **세션은 매일 한국 시간 자정에 만료.** 다음 날 다시 로그인해야 하므로 "그날 첫 로그인 = 출근"이 성립한다.
- **관리자도 출퇴근 기록 대상.** 관리자 계정으로 로그인해도 출근이 기록된다.
- **퇴근 취소 가능.** 실수로 눌렀으면 그날 안에 "퇴근 취소" 후 다시 누를 수 있고, 마지막 값이 남는다. 출퇴근은 하루 한 행(날짜별). 자정을 넘기는 근무는 고려하지 않는다.
- **반복 업무 회차별 예외 없음(1차 범위).** 특정 날만 건너뛰거나 그날만 제목·담당자를 바꾸는 기능은 넣지 않는다. 반복 업무 정의를 수정하면 과거 회차의 상태·메모 기록은 남고, 제목은 현재 정의 기준으로 보인다.
