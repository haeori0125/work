# 팀 투두 화면 개편 — 설계 문서

작성일: 2026-11-23 · 상태: 승인 대기
기준 시안: https://claude.ai/artifact/X3KGEcW3EEdqX2qBFmPj3L (9판)
이전 설계: `docs/superpowers/specs/2026-11-23-team-todo-design.md` (기능은 그대로, 아래에서 바뀌는 것만 적음)

## 1. 목적

주로 PC로 접속하는 모임 멤버가 한 화면에서 오늘 할 일과 이번 주 전체를 함께 보게 한다. GoodTask·아이폰 미리알림처럼 깔끔한 카드형 화면에, 사람마다 자기 색과 보기 방식을 정할 수 있게 한다.

## 2. 목표 / 비목표

**목표**
- 화면 전체 글꼴 Pretendard
- 홈: 왼쪽 "오늘"(세로로 길게), 오른쪽 위 "위클리"(7칸 한 번에), 오른쪽 아래 "메모"(위클리와 같은 폭)
- 미리알림식 둥근 체크 원: 누를 때마다 미완료 → 진행 중 → 완료
- 사용자별 설정 탭: 테마 색, 위클리 시작 요일, 진행 중·완료 색
- 개인 메모 여러 장(아이폰 메모식)
- 하루 여러 번 출퇴근 구간 합산, 퇴근하면 자동 로그아웃
- 휴대폰 폭에서도 깨지지 않음(가로 스크롤 없음)

**비목표**
- 기능 추가는 위 목록뿐. 업무·승인·관리 규칙은 이전 설계 그대로
- 메모 첨부파일, 메모 공유, 폴더
- 위클리에서 업무 새로 만들기(작성은 계속 관리자 화면)

**실패 조건**
- 테마 색에 따라 글자가 배경에 묻혀 안 읽힘
- 하루 여러 구간 중 일부가 근무 시간 합계에서 빠짐
- 퇴근 후 다시 로그인했는데 새 구간이 안 생김

## 3. 접근 방식

| 방식 | 내용 | 판단 |
|---|---|---|
| **A. 기존 Next.js 앱의 화면과 데이터 구조를 고친다** ✅ | 지금 배포된 앱 위에서 CSS 토큰·컴포넌트를 바꾸고, 설정·메모·출퇴근 테이블을 마이그레이션으로 바꾼다 | 기능·테스트·배포가 이미 있음 |
| B. UI 라이브러리(Tailwind/shadcn 등) 도입 후 다시 짜기 | 컴포넌트를 새로 갈아끼움 | 바꿀 범위가 커지고 얻는 게 적음 |
| C. 시안 HTML을 그대로 붙이기 | 정적 시안을 그대로 사용 | 실제 데이터·권한과 연결이 안 됨 |

한 가지 방식(A)이 분명해서 A로 진행한다.

## 4. 정해진 것 (사용자 결정)

### 4.1 공통
- **글꼴:** Pretendard. npm `pretendard` 패키지의 가변 글꼴을 앱에 포함해 쓴다(외부 CDN 의존 없음).
- **줄바꿈:** 사이트 전체 어절 단위(`word-break: keep-all`).
- **상태 이름:** "미체크" → **"미완료"**. 상태 값(`todo/doing/done`)은 그대로.
- **체크 원:** 빈 원(미완료) → 반 채운 원(진행 중) → 꽉 찬 원 + 체크(완료). 원을 누를 때마다 다음 상태로 순환. 아래에 "진행 중 · 이영희 09:14"처럼 바꾼 사람·시각 표시.

### 4.2 상단
- **출퇴근 줄(상단 바 위, 별도 카드):** 이름, "근무 중" 표시, "11월 23일 (월) · 출근 09:02", 오른쪽 끝 **빨간 "퇴근하기" 버튼(색 고정)**. 좁은 화면에서도 버튼은 오른쪽 끝, 크기만 조금 작아지고 날짜 줄은 아래로.
- **상단 바:** 브랜드 "팀 투두", 탭 **홈 · 내 기록 · 개인 메모 · 설정 · (관리자) 관리**, 오른쪽 이름 머리글자 원. 바 색 = 테마 색.

### 4.3 홈
- **오늘(왼쪽, 세로로 길게):** 제목 "오늘" + 날짜 + 남은 개수. 작은 요약 칸 3개(남은 일 / 진행 중 / 지난 업무, 한 줄 높이). 그 아래 "지난 업무"(빨간 소제목), "오늘 할 일". 관리자에게만 "＋ 새로운 할 일" → 관리 화면으로 이동.
- **위클리(오른쪽 위):** 제목 + 기간 + "○요일 시작". 맨 위 띠에 "이번 주 업무"(날짜 없는 주간 업무, 알약 모양, 체크 가능). 그 아래 7칸 한 번에. 칸 머리: 날짜 숫자 + 요일 + "완료/전체". 오늘 칸 강조, 일요일 요일 글자 빨강, 지난 날 칸은 흐리게. 칸 안에서 바로 체크 가능.
- **메모(오른쪽 아래):** 오늘의 공용 메모. 메모 카드들 + 오른쪽 입력 칸.
- 좁은 화면: 오늘 → 위클리 → 메모 순서로 세로로 쌓이고, 위클리 7칸은 2칸씩.

### 4.4 설정(사용자별, 계정에 저장 — 다른 PC에서도 같음)
- **테마 색:** 원형 색상환(각도 = 색, 가운데에서 거리 = 채도), 밝기 막대("진하게 ↔ 연하게", 기본은 연한 파스텔), 색상 코드 6자리 입력(# 있어도 됨, 틀리면 "색상 코드는 # 뒤에 6자리로 입력하세요" 안내), 추천 파스텔 8개, "기본 색으로". 고른 색 하나에서 배경·카드·선·글자색까지 전부 계산. 밝은 바탕 위 글자는 자동으로 진한 색. 입력한 색상 코드는 그대로 표시.
- **위클리 시작 요일:** 일요일 시작 / 월요일 시작(기본 월요일).
- **진행 중 · 완료 색:** 각각 "자동 / 직접 선택". 자동 = 진행 중은 테마 색에서 색상환을 40° 돌린 이웃 색, 완료는 테마 색. 직접 선택 = 추천 10색 또는 색상 코드. 미리 보기 줄.
- 바꾸면 바로 저장. 라이트/다크는 기기 설정을 따름(테마 색은 두 모드 모두 적용).

### 4.5 내 기록
- 왼쪽: "내 기록" + 달 이동(‹ ›, 다음 달은 이번 달까지만), 요약 4칸(근무한 날 / 총 근무 시간 / 평균 출근 / 퇴근 미기록 건수), 달력(근무한 날 테마 색, 미기록 빨강, 오늘 테두리).
- 오른쪽: 날짜별 출퇴근. 6시~24시 눈금 위에 **구간마다 막대**, 막대 아래 줄에 구간 시각들, 오른쪽에 **구간 합계** + "n회 합산" / "근무 중" / "수정됨" / "퇴근 미기록".

### 4.6 출퇴근 규칙 (변경)
- **로그인 = 새 구간 출근.** 단, 그날 아직 퇴근 안 한 구간이 열려 있으면(다른 기기 등) 새 구간을 만들지 않는다.
- **퇴근하기 = 열린 구간 종료 + 자동 로그아웃.** 그 사람의 모든 세션을 끝낸다. (기존 "퇴근 취소"는 없앰 — 다시 로그인하면 새 구간이 생김)
- **근무 시간 = 그날 모든 구간 합.** 구간의 날짜는 출근 시각의 한국 날짜.
- **퇴근 미기록:** 자정이 지났는데 퇴근 시각이 없는 구간이 있는 날. 그 구간은 합계에서 빠지고 관리자가 고칠 수 있음.
- **평균 출근:** 그날 첫 구간 출근 시각의 평균.
- 관리자 출퇴근 화면: 구간 단위로 출근·퇴근 시각 수정, 수정 이력 유지.
- 기존 데이터(하루 한 행)는 구간 1개로 옮긴다.

### 4.7 개인 메모 (여러 장)
- 왼쪽 목록: 제목(첫 줄, 비면 "새로운 메모"), 날짜 + 미리 보기, "📌 고정됨" 묶음이 위, 최근 수정순. 검색, "＋ 새 메모".
- 오른쪽 편집: 쓰는 대로 자동 저장(입력 멈추고 잠시 뒤 저장), 글자 수, 고정/고정 해제, 삭제(한 번 더 눌러 확인).
- 휴대폰: 목록 ↔ 편집 화면 전환, "‹ 메모"로 돌아감.
- 기존 개인 메모 한 장은 첫 메모로 옮긴다.

### 4.8 관리 화면
- 기능은 그대로, 새 디자인 토큰(카드·버튼·글꼴·테마 색)으로 다시 칠한다.

## 5. 빌더 판단 사항
- 설정 저장 위치: `user_prefs` 테이블(사용자당 1행) 권장. 첫 화면 깜빡임 없게 서버에서 읽어 `<html>`에 CSS 변수로 넣기.
- 색 계산은 CSS 변수(`--h --s --l`, 진행 중 `--dh --ds --dl`, 완료 `--oh --os --ol`)와 `hsl()` 계산으로 — 시안과 같은 공식.
- 메모 자동 저장 간격(예: 입력 멈춘 뒤 0.8초), 메모 최대 길이(장당 2만 자), 개수 제한 없음.
- 위클리 7칸이 좁을 때 업무 이름은 어절 단위로 줄바꿈.
- 테스트: 출퇴근 구간 합산·자동 로그아웃·열린 구간 재로그인, 설정 저장·검증(색상 코드 형식), 메모 CRUD·권한(남의 메모 접근 불가)은 단위 테스트, 홈·설정 흐름은 E2E.
